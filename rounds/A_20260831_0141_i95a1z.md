## Adversarial review (done against myself before commit)

- First draft of the wiring call, `emit(world_m2_sea_destination.
  console_line_safe(registry))` with the DEFAULT `registry=None` call
  (matching how the dispatch function is invoked from the isolated test
  suite), raised `SeaDestinationError` uncaught the first time I ran the
  targeted tests -- `_target()` refuses `None` on purpose, and my own first
  `console_line_safe` draft folded that into the generic `except Exception`
  branch, producing an opaque `reason=refused:SeaDestinationError` instead
  of the specific, already-established `call_site_passed_no_<thing>` shape
  this file's siblings use. Caught by running the tests, not by review;
  fixed by naming the `None` case explicitly and adding a test that pins
  the exact string, and a companion test proving the measured line still
  matches `console_line()` byte-for-byte when a real registry is passed.
- Mutation check (by hand, no subagent tool available in this environment):
  swapping `console_line_safe` for the raising `console_line` at the call
  site turns the isolated-harness tests (registry=None) into an uncaught
  exception instead of a returned `SceneEntry` -- caught. Swapping the
  `if registry is None` branch order, or moving the new `emit()` call
  before the crossing-handoff line instead of after, are both caught by
  the position-pinned assertions in `test_columbus_quest_dispatch.py` and
  `test_world_m2_crossing_handoff.py` (both updated this round to account
  for the new line, using the same "was true, now shifted by one, and the
  test's own name explains why" convention the file already used four
  times for earlier additions).
- Existing tests in `tests/test_world_m2_crossing_handoff.py`
  (`DispatchPrintsTheLineTests`, four tests) assumed the crossing-handoff
  line was `lines[-1]`; it is now `lines[-2]`. Fixed in place with a
  one-line comment pointing at the correction, per house rule (strike, do
  not delete silently) -- these are this lane's own file (`world_m2_
  crossing_handoff.py`'s test suite is a sibling M2 module, in the same
  write zone), not another lane's.
